# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A speechwriter agent built on **Deep Agents** (`deepagents` on LangChain/LangGraph). The project mostly *configures* the harness rather than implementing agent machinery: filesystem tools, subagent delegation, and skills all come from `create_deep_agent`. The code supplies the model, the prompts, the backend routing, the permission sandbox, and durable memory.

## Commands

```bash
uv sync                                  # install into .venv from uv.lock
uv run speechwriter                      # interactive REPL (also: uv run python -m speechwriter)
uv run streamlit run streamlit_app.py    # the web UI (same bundle, second front end)
uv run pytest                            # full suite — offline, no API key or network
uv run pytest tests/test_build.py::test_write_sandbox_confines_writes   # single test
uv run python evals/validate_datasets.py # the 55 eval datasets vs the live contract (bare `python` won't resolve the import)
uv run python evals/sync_datasets.py     # check the LangSmith mirror is intact (add --push to make it so; needs a key + network)
uv run python evals/run_experiment.py --dry-run          # score a canned run offline — checks the eval wiring for free
uv run python evals/run_experiment.py --limit 1          # one LIVE graded run against the trajectory set (costs tokens)
uvx ruff@0.16.0 check .                  # lint (line-length 100)
uvx ruff@0.16.0 format .                 # format
uvx ty@0.0.63 check                      # type check
printf 'exit\n' | uv run speechwriter    # zero-cost smoke test: builds, banners, persists, exits — no model calls
printf 'BRIEF\nexit\n' | uv run speechwriter   # drive one real turn non-interactively (costs tokens)
```

**When working with Python here, invoke the relevant Astral skill first** — `/astral:uv` for dependencies and environments, `/astral:ruff` for lint and format, `/astral:ty` for type checking — so the current best practices are followed rather than guessed at. They also encode the right invocation form: `uv run` for anything that must import the project's dependencies (e.g. `pytest`), `uvx` for standalone tools (`ruff`, `ty`).

### Environment

`load_settings()` reads seven variables, and its docstring (`config.py`) is the roster — `TAVILY_API_KEY`, `SPEECHWRITER_MODEL`, `SPEECHWRITER_MAX_TOKENS`, `SPEECHWRITER_MAX_RESEARCH_RESULTS`, `SPEECHWRITER_HOME`, `SPEECHWRITER_BASE_URL`, and `OPENAI_API_KEY`. **`ANTHROPIC_API_KEY` is no longer one of them** — there is no hosted client to send it to (see *There is one client* below), and `Settings.anthropic_api_key` was removed rather than kept as a vestigial field, because a key the agent can never send reads as a credential in use. The startup gate it fed is now `model_endpoint_usable`: the CLI still *warns* with a panel and refuses commissions per turn while `build_agent()` does neither, and `speechwriter` on a misconfigured endpoint still exits 0 rather than 1, so `/endpoint` stays reachable for the reader that panel addresses. Both integer knobs go through `_optional_int_env`, which *warns and falls back* rather than raising, so a typo'd value costs a log line, not a crash.

**`SPEECHWRITER_HOME` overrides `project_root`, and everything else derives from it** — workspace, skills, store path, and which dotenv file gets loaded. There is no `tests/conftest.py`; it is the suite's *only* isolation mechanism, and **every** test that reads or writes anything sets it by hand (61 sites across four files at the time of writing — the rule, not the number, is what to remember: a count here has gone stale twice). A new test that forgets it reads and writes the real repo. Note the trade-off it carries: `load_settings()` creates `workspace_dir` and the store's parent but **never `skills_dir`**, and `create_deep_agent` only logs when a skills tree is missing — so every test pointing `SPEECHWRITER_HOME` at a `tmp_path` runs with the rhetoric library silently absent. Nothing in the suite exercises real skill loading; `test_all_skills_have_valid_frontmatter` reads the files off disk instead.

All three gates are **clean** and must stay that way: `uv run pytest`, `uvx ruff@0.16.0 check .`, and `uvx ty@0.0.63 check`. **Type the pins.** Unpinned, `uvx` resolves whatever Astral shipped today, and a checker one version off CI can demand a suppression that CI then rejects as unused — a state no source satisfies (see the pin rule under Automation). (No pass-count is quoted here on purpose — it went stale twice in one sitting, and `pytest` reports the number better than a doc can.) Prefer typing something precisely over widening it to `Any`; if a suppression is genuinely unavoidable, use a rule-specific `# ty: ignore[rule-name]`, never a blanket `# type: ignore`.

## Architecture

Everything composes in one place: `build_agent()` in `src/speechwriter/agent.py`. Read that file first; the rest of the package feeds it.

### The virtual filesystem is the central design

The agent sees a `CompositeBackend` that routes by path prefix. Virtual paths are **not** real paths — `FilesystemBackend` is rooted at `project_root` with `virtual_mode=True`.

```
/skills/     → FilesystemBackend   read-only reference (the rhetoric library)
/workspace/  → FilesystemBackend   real .md files on disk (drafts, research notes)
/memories/   → StoreBackend        intercepted before disk; never a real folder
```

### Paths are single-sourced in `config.Settings` — and four consumers must agree

`memories_vpath` is a `ClassVar` (`/memories/`); `skills_vpath` and `workspace_vpath` are properties derived from real dirs via `Settings._vpath()`. Four independent consumers depend on them agreeing:

1. **Backend routes** — `agent.py:_build_backend()` routes `memories_vpath` to the Store. *(`test_backend_routes_memories_to_the_store_and_everything_else_to_disk`)*
2. **Sandbox rules** — `agent.py:_write_sandbox()` allows writes only under workspace + memories. *(`test_write_sandbox_confines_writes`)*
3. **Prompt text** — `prompts.py` interpolates all three paths into the system prompts. *(`test_every_virtual_path_reaches_the_prompts`)*
4. **README's routing table** — documentation, and the first thing a reader meets. *(`test_readme_routing_table_matches_the_configured_paths`)*

Change a path and you must propagate it through all four, or the agent will be *instructed* to write somewhere the sandbox *denies*.

This used to be enforced by nothing but an advisory Claude Code hook that restated the rule on a `config.py` edit. It is now four tests, which is strictly stronger: they run in CI and for contributors not using Claude Code, and they *block*. Two things they encode deliberately. The backend consumer is tested through `_build_backend()` — extracted from `build_agent()` for exactly this reason, since a route buried in a local cannot be asserted against without compiling the graph — and it asserts the **behaviour** (a `/memories/` write reaches the Store and never becomes a real folder), not just the route key, because that is the property the design exists for. And a *consistent* rename must keep passing: the prompt interpolates from `Settings`, so only hard-coded drift should fail. That is why README, which spells the paths out as prose, is the consumer that catches a rename.

The trailing-slash asymmetry is deliberate and load-bearing: `skills_vpath` and `memories_vpath` carry a trailing slash, `workspace_vpath` does not, because `prompts.py` renders `{workspace_vpath}/speeches/<slug>.md`. Normalizing them for tidiness silently yields `/workspace//speeches/` — which is why the prompt test asserts no rendered prompt contains `//`.

Likewise `SPEECHES_SUBDIR` / `RESEARCH_SUBDIR` / `WORDS_PER_MINUTE` are single-sourced in `config.py`: `prompts.py` *tells* the agent to file drafts under those folders at that pace, and `workspace.py` *reads* them back to list drafts and estimate spoken length. Re-hardcoding either side yields a browser that silently lists nothing — `test_prompts_point_the_agent_at_the_folders_the_browser_reads` guards the folder seam (both halves: `browse.py` lists `research_dir()` as well as `speeches_dir()`, and the researcher subagent that writes there is steered by its own prompt, so that prompt gets its own case), and `test_spoken_length_uses_the_pace_the_prompt_prescribes` parses the pace back out of the rendered prompt rather than reading `WORDS_PER_MINUTE` on both sides. Both were mutation-tested: hard-code the folder or the pace into `prompts.py` and they fail. Note `ruff` will *not* save you here — re-typing one constant leaves the others imported, so F401 never fires.

### The write sandbox is enforced, not prompted

`_write_sandbox()` returns first-match-wins `FilesystemPermission` rules: allow `write` under workspace + memories, then deny `write` on `/**` as the backstop. Reads are left open so skills and reference material still load. The same rules are applied **twice** — to `create_deep_agent(permissions=...)` *and* to every subagent — because each subagent is built with its own `FilesystemMiddleware`. Passing them explicitly is belt-and-braces rather than the only thing between the critic and the repo: `graph.py`'s `spec.get("permissions", permissions)` means an *omitted* key falls back to the parent's rules (true across the whole pinned range, not just 0.7). But the fallback is all-or-nothing — an explicit list **replaces** the parent's entirely — so if you pass one, keep it complete. Skills are the key that genuinely inherits nothing.

### Subagents inherit nothing

`build_subagents()` must hand each subagent everything it needs explicitly:
- **Skills** — the `style-critic` gets `"skills": [settings.skills_vpath]` because subagent skill sets are not inherited.
- **Permissions** — passed in from `build_agent` as the `permissions=` argument. (These *would* be inherited if omitted — see the sandbox section above. Skills and cross-call state are the two that genuinely are not.)

Subagents are also stateless across `task` calls; the orchestrator prompt says so, and any new subagent must be given complete self-contained instructions per call.

Because "inherits nothing" makes every key load-bearing, `build_subagents()` returns `list[SubAgent]` — deepagents' `TypedDict`, not `dict[str, Any]`. That is deliberate: a typo like `"skill":` for `"skills":` would *not* fail at runtime, the `style-critic` would just silently lose the rhetoric library. Typed, `ty` rejects the unknown key. Keep the precise type when adding a subagent.

### There is one client, and every model is served locally

**This project runs on locally served models only.** There is no Anthropic path and no hosted fallback: `_build_model` builds a `ChatOpenAI` unconditionally, stating `model_provider="openai"` because a local id like `mlx-community/Qwen3.8-27B-4bit` carries no provider prefix for `init_chat_model` to infer. `SPEECHWRITER_MODEL` and `SPEECHWRITER_BASE_URL` are two halves of one decision and default *together* (`DEFAULT_MODEL` + `DEFAULT_LOCAL_ENDPOINT`, `mlx_lm.server`'s own port) — defaulting the id alone leaves a model with nowhere to send it. Four things are load-bearing.

**The ceiling is two tiers: `SPEECHWRITER_MAX_TOKENS`, else `DEFAULT_MAX_TOKENS`.** There used to be a middle tier keeping a ceiling the client had resolved for itself, and it is gone *by construction*, not by preference: `init_chat_model` fills `max_tokens` from a model profile only on the Anthropic path, so with `ChatOpenAI` it can never fire — not even for a profiled id like `gpt-4o` behind LiteLLM, whose `max_tokens` comes back `None`. A branch that reads as live protection and is dead is worse than no branch. Its removal also removed the reason `_build_model` logged at all, which is why that module now has no logger: an unprofiled id used to mean a typo, and now means every id, so a line per build would be noise. `ceiling_label` and `TruncationWarner` are what report the ceiling instead.

**`DEFAULT_MAX_TOKENS` (12288) is bounded from *both* sides, and the lower one is easy to forget.** Above, by `DEFAULT_LOCAL_CONTEXT_WINDOW` (32768): output and input share one window on a local server, and 32000 — sized when the ceiling applied to 128k-window hosted models — leaves 768 tokens for the entire prompt, which vLLM rejects outright and others clamp silently. Below, by the longest draft anyone commissions: the ceiling is also the *thinking* budget, and the largest committed eval example asks for 3,250 words (~4.5k tokens) before the model reasons at all. A first pass chose 8192 by halving against the window alone — which is how a ceiling ends up truncating the commission the datasets grade most heavily. `test_the_default_ceiling_fits_inside_the_assumed_context_window` pins both directions, reading the floor out of `evals/datasets/` so a longer example moves it. `SpeechwriterAgent.ceiling_crowds_context` (which replaced `ceiling_exceeds_model`) flags a ceiling above **half** the window, and both front ends render it on a line of its own.

**The ceiling leaves as `max_completion_tokens`**, not `max_tokens` — `test_the_resolved_ceiling_reaches_the_request_payload` asserts the *value* rather than either spelling, since a rename upstream would silently unbound a local reasoning model. `mlx_lm.server` reads the new key; older shims may read only the old one.

`model_endpoint_usable` — which replaced `model_credentials_present` — is what both front ends gate on. The old question ("is a key present") became true for every configuration once the hosted client left, and a gate that is unconditionally true is a gate that has quietly stopped running. The new one is a **shape** check (`endpoints.usable_endpoint`), never a probe: it rejects a non-`http(s)` scheme and a hostless URL, which is exactly the set of failures visible without opening a socket. Reachability stays a runtime concern — that is what **Detect models** and `/endpoint` are for.

**Every test that builds a model or renders a page still `delenv`s `SPEECHWRITER_BASE_URL` by hand**, and with no `conftest.py` that is the only isolation there is — but it now means *"pin the documented default pair"* rather than *"select the Anthropic client"*. Re-read what a given `delenv` is asserting before copying it. (Don't trust a count here: this doc said 27 while the tree held 40, the same way the `SPEECHWRITER_HOME` count went stale twice. The rule is what to remember.)

`_build_model` still touches no network — `base_url` is recorded, never probed — so the offline invariant holds and an unreachable server fails at the first turn instead of at build time.

**The model is given a `profile`, and that is about input, not output.** deepagents sizes its context-compaction trigger from the model's LangChain profile: a profiled id compacts at a *fraction* of its real window, an unprofiled one gets a flat `('tokens', 170000)`. Every local id is unprofiled, and no local server has a 170k window — so without this the plan/draft/critique/revise rhythm outgrows the window and the server errors before compaction ever fires. `_build_model` passes `profile={"max_input_tokens": settings.context_window or DEFAULT_LOCAL_CONTEXT_WINDOW}`. Three things about it. It does **not** touch the ceiling — `init_chat_model` applies a profile's `max_tokens` only on the Anthropic path, so the ceiling still resolves through the two tiers above and the payload key stays `max_completion_tokens`. Only `max_input_tokens` is carried: a `max_output_tokens` key here is *inert* (measured), and would imply a ceiling mechanism this path does not have. It **replaces** any profile the id would otherwise have, which matters only for a profiled id served locally (`gpt-4o` on LM Studio) — and is deliberate: a local server's model *name* tells you nothing about the window it actually loaded, so inheriting the hosted `gpt-4o` profile is a guess, while the floor is merely conservative. The cost is real and worth knowing: that model compacts at ~28k instead of ~108k. `ModelChoice.context_window` is the per-entry escape hatch, and the same value reaches `SpeechwriterAgent.context_window` so `ceiling_crowds_context` compares against the window actually in force. And `context_window` is a `Settings` field that is **never read from the environment** — it is set only by `dataclasses.replace`, because a `SPEECHWRITER_CONTEXT_WINDOW` knob would trip the `.env.example` gate described under Automation, and it is a property of a chosen model rather than of the machine. `test_a_local_choice_compacts_before_its_context_window` asserts the trigger is a *fraction* rather than an exact figure, since the fraction is deepagents' own default and may move while a flat token count is the actual failure.

**The client kwargs are a `TypedDict` (`_ClientKwargs`), not an inferred dict.** Same reasoning as `list[SubAgent]`: `init_chat_model` takes `**kwargs: Any`, so a misspelled `"profiles"` would be accepted, forwarded into the client constructor's own `**kwargs`, and cost you compaction silently. It is **total** now that the client is unconditional — the old `total=False` paid for exactly one thing, describing the empty dict the hosted branch passed, and with that branch gone a missing key should be a type error rather than a silent fallback.

### The model is selectable at runtime, and a choice is a *pair*

`config.ModelChoice` is a `NamedTuple` of `(label, model, base_url, context_window)`, and `base_url` is **not optional** — it defaults to `DEFAULT_LOCAL_ENDPOINT`, never to `None`. The model and the endpoint travel together because they are **not independent**: an id names weights, and the same weights served by two machines are two different systems to talk to. Pairing them makes an id-with-nowhere-to-send-it unrepresentable rather than something every front end must remember to validate. **Never let a UI produce `model` and `base_url` separately.**

`MODEL_CHOICES` is the **empty tuple**. It held three curated Anthropic ids while there was a hosted client to call them with; it is kept as a name because it is still the seed `model_choices()` builds on, but it must not be repopulated with local entries. Two reasons, and both are load-bearing:

- **A fixed roster silently retargets a configured user.** Streamlit replaces a `session_state` value that is not among a widget's options with option zero — no exception, no log (verified). So a reader whose server is on some other port would be moved onto whichever entry happened to be first.
- **Hard-coded local endpoints are dead entries.** They are a guess about which server the reader is running, and every guess that misses is a row that 404s when selected; synthesising from `SPEECHWRITER_BASE_URL` is correct by construction because the operator configured it. `speechwriter.endpoints.list_models` widens it further, on demand.

Note where the non-empty guarantee moved to: `model_choices()` synthesises an entry for **every** configuration handed to it, and both front ends always hand it at least one, so the roster a picker sees is never empty even though the seed is. `streamlit_app.py` indexes it (`choices[0]`) and depends on exactly that.

**`model_choices` is variadic, and passing only the live settings is a bug** — the first version did, and it shipped a one-way trip. It survives the empty seed, because the seed is what used to make a *curated* entry findable after a switch: with nothing curated, a roster rebuilt from the post-switch settings alone drops the configured pair the reader came from, and switching from it to a detected model on a second server is then unrecoverable without a restart. Callers therefore pass **both** the configuration the session started on and the one now in force — `webui.base_settings()` (a separate `cache_resource` that `switch_model` deliberately does *not* invalidate, because a pick does not change what the environment says) and `cli.main`'s `configured` local. The same rule governs the Detect button and the endpoint caption: both key off the *configured* endpoint, not the selected model's. `test_switching_away_from_a_local_model_leaves_a_way_back` is the guard.

**Known limitation, not a bug to fix casually:** `get_bundle` is a process-global `cache_resource` whose body reads *per-session* state, so with two browser tabs open the second tab's picker can show a different model than the one actually running. That is the same trade `get_bundle`'s docstring already makes for the shared Store and the shared `warner` — honest for a local single-user app, and the alternative (keying the cache per session) reintroduces the multi-Store snapshot clobber. Do not "fix" it by parameterising the cache.

Labels are built by `config.local_choice` in exactly one place, and that is correctness rather than tidiness: `ModelChoice` is a `NamedTuple`, so two entries for the same served model compare equal only if their labels match too — and a detected entry that differed by a label would appear twice *and* leave the selected one unfindable among the options, which is the silent-rewrite trap again.

**The switch is the same three steps everywhere, and the order is the argument:**

```
bundle.persist()                              # 1. FIRST — save_store rewrites wholesale
bundle = build_agent(choice.applied_to(settings))   # 2. all three fields move together
thread_id = <fresh>                           # 3. the old checkpoint no longer exists
```

`ModelChoice.applied_to()` and `.is_current()` exist so those two questions are asked in one place each. `applied_to` moves `model`, `base_url` and `context_window` **together** — applying the model alone leaves one server's id pointed at another server's address, or a model compacting for the previous one's window. `is_current` compares the *pair*, never the label, because two entries naming the same model at the same endpoint are the same choice however they are captioned — and a comparison that dropped `base_url` would call the same weights on a laptop and on a workstation identical.

1. `build_agent` rehydrates a **brand-new** `InMemoryStore` from the on-disk snapshot, so everything learned this session is dropped unless it is written first. Reversing 1 and 2 loses voice profiles with no error at all. Asserted three ways, because two of them were added only after a review found the web side uncovered — deleting `persist()` from `switch_model` passed the whole suite: `test_switching_models_carries_learned_memory_across_the_rebuild` (the property), `test_the_model_command_persists_before_it_rebuilds` (CLI order), `test_switching_models_in_the_browser_saves_before_it_invalidates` (web order).
2. A rebuild is required, not merely tidy: the resolved ceiling is read off the *constructed* client, so a swap that reused the bundle would leave both banners quoting the previous model's.
3. `build_agent` also mints a fresh `MemorySaver`, so the old `thread_id` names a checkpoint the new graph has never seen. The CLI rotates it exactly as it does after an interrupt; the web UI calls `reset_conversation()`, which already does all four required things.

Three designs that look right and are **wrong**, each disproven by measurement — do not revisit them:

- **Parameterising `webui.get_bundle(model)`.** `st.cache_resource` keys on arguments, so each model gets its own bundle with its own Store, all snapshotting to one file that `save_store` replaces wholesale. Reproduced as real data loss. `get_bundle` stays **zero-arg** and reads the choice from session state inside its body; `switch_model` invalidates it with `get_bundle.clear()`.
- **`st.cache_resource.clear()` instead of `get_bundle.clear()`.** The global form evicts *every* `cache_resource` cache, including `spoken_length`'s WAVs — while `browse.py`'s per-session "already measured" flags survive, sending the next render straight back into a ~9s synthesis with no button pressed.
- **Swapping the model per-turn with `wrap_model_call` middleware.** The orchestrator switches and the **subagents do not** — measured call order `['B','A','B']` — because deepagents binds `spec.get("model", model)` at build time. (Note the corollary: `model` is one of the few things a subagent *does* inherit, so the rebuild path propagates a switch to `researcher` and `style-critic` for free.) Relatedly, `init_chat_model(..., configurable_fields=...)` returns a `_ConfigurableModel` that is not a `BaseChatModel` and `create_deep_agent` rejects it outright.

**`SPEECHWRITER_MAX_TOKENS` is tier 1 and global, so it follows a switch.** An override sized for one model outlives it, and served locally that bites harder than it did against a hosted ceiling: output and input come out of the *same* window, so the override starves the prompt rather than merely being refused. `SpeechwriterAgent.context_window` carries the window in force — resolved the same way `_build_model` resolves it, `settings.context_window or DEFAULT_LOCAL_CONTEXT_WINDOW`, so a choice that named no window still reports the floor rather than `None` — and `ceiling_crowds_context` is the comparison. Both front ends already print the ceiling, which is why the warning is a second line beside it rather than a second channel.

**Four things a review caught that the first version got wrong**, all now tested — they are the shape of mistake this design invites, so read them before changing the switch:

- **The roster was derived from the live settings, making the switch one-way** (above). Four independent reviewers found it; nothing in the suite did.
- **`switch_model` asked `get_bundle()` whether the pick was already running.** That reads the *new* choice from session state, so on a cold cache it built the new model, matched itself, and returned before `reset_conversation()` — leaving a transcript whose thread names a checkpoint the fresh `MemorySaver` never saw. A cold cache at callback time is ordinary: `cache_resource` is app-global, so one tab switching clears it for every other. There is now **no guard at all**, because Streamlit fires `on_change` only when the value actually changes (verified), so the case it defended against cannot arise.
- **The trailing bundle field was inserted before `warner`** rather than appended — the rule `config.Settings` spells out, broken in the class next door. A default is not enough: a consumer constructing the bundle positionally would have bound their warner to that field. `test_the_bundle_still_takes_its_fields_in_the_documented_order` now pins the order, and it still applies: `context_window` replaced `profiled_max_tokens` **in place**, at the end, rather than being slotted anywhere tidier.
- **The over-ceiling warning was folded into `ceiling_label`.** Both front ends interpolate that label into a sentence telling the reader to *raise* `SPEECHWRITER_MAX_TOKENS`, so folding the warning in produced advice arguing with itself. The label is a bare figure; `ceiling_crowds_context` is the separate question, rendered on its own line.

**`get_bundle` catches a failed build rather than raising.** It runs at module scope in `streamlit_app.py`, *above* the sidebar, so an unbuildable pick would take the page down before the picker that undoes it is drawn — and the pick survives in session state, so every rerun raises again. It falls back to the environment's model, drops the bad selection, and leaves the reason in `_BUILD_ERROR` for the sidebar to report. This mirrors the guard `cli._switch_model` already had; the browser simply lacked it.

**`endpoints.py` is the one module that opens a socket on purpose**, and it is reached only from a click handler or the REPL's `/endpoint` — never at import, never on render, and deliberately **not** from the endpoint field's `on_change`. A probe on blur reads as a user action but fires on every tab away from the box, and when an edit and a click arrive in one interaction Streamlit runs `on_change` first, so the server is asked twice for one gesture — up to two full `DEFAULT_TIMEOUT`s of blocked rerun against a host that black-holes. `build_agent()` must not touch the network, and CI renders the Streamlit app dozens of times per run. It uses stdlib `urllib`, not the `openai` SDK: `openai` reaches this environment only transitively via `langchain-openai`, so importing it would repeat the undeclared-dependency trap documented for `pyyaml` under Gotchas. Every failure returns `[]` rather than raising — including the one that bites, a `base_url` with no scheme, where `urllib.request.Request` raises at **construction** before any socket, so the `try` has to wrap the request-building too — and, since `a304a89`'s successor, the *scheme read* as well: `urlsplit` raises `ValueError: Invalid IPv6 URL` on an unclosed bracket, which was unreachable while an endpoint came only from a dotenv and is one keystroke away now that it can be typed. And `_ids` guards the shape because a running Ollama with nothing pulled answers `{"data": null}`: `data` is `None`, not `[]`, and the blanket `except` would otherwise file a healthy server under "could not list". That last distinction is invisible in the return value — both paths give `[]` — so its test asserts on the **log**, after a first mutation run showed the return-value version passing vacuously.

Two of its guards are about credentials rather than robustness, and both were review findings with working reproductions. **The scheme is checked explicitly** because `urlopen`'s default opener installs `FileHandler`, `FTPHandler` and `DataHandler` — so `SPEECHWRITER_BASE_URL=file:///Users/you/private` made the Detect button read `/Users/you/private/models` off local disk and list what it found. `build_opener` cannot do that job; it re-adds every default whose class was not passed in. And **`_CredentialSafeRedirects` strips `Authorization` on a cross-origin hop**, because `HTTPRedirectHandler.redirect_request` copies every header but content-length and content-type onto the new request — so an endpoint answering `/v1/models` with a 302 elsewhere handed the reader's real `OPENAI_API_KEY` to wherever it pointed (measured). Same-origin keeps it; that is the server it was configured for. `DEFAULT_TIMEOUT` is 10s, sized not for the fast paths but for the slow *healthy* one: `mlx_lm.server` answers by walking the whole HuggingFace cache, and too short a timeout turns a working server into an empty list.

### An endpoint can be typed at runtime, and detections are bound to it

`SPEECHWRITER_BASE_URL` used to be the *only* way a locally served model reached the roster, and every local path was gated on it: `available_choices` widened from `base_settings().base_url`, the Detect button rendered inside `if endpoint:`, and `cli.main` called `raise SystemExit(1)` before the loop when no model could be called. So the one reader the feature is for — a running server on some port other than the default, nothing configured — had to edit a dotenv and restart to reach controls whose whole job is sparing them that. The sidebar's **Local endpoint** field and the REPL's `/endpoint <url>` close that, session-only, in both front ends.

**The load-bearing rule is that a detection is a *pair*, created the moment it is detected.** `webui`'s `DETECTED_KEY` holds `list[ModelChoice]`, never `list[str]`. Pairing ids with an endpoint at *read* time was sound only while the endpoint could not change; it can now, so ids found at one server would be relabelled as served by another the moment the box was retyped — a `(model, base_url)` naming a server the model is not on, which `_build_model` turns into a client pointed straight at it. Detected as a pair, stored as a pair, offered as a pair; `test_detections_stay_bound_to_the_server_that_answered` is the guard, and the change *deleted* the re-pairing block rather than adding a check to it.

**`model_choices(*offered, detected=())` merges `detected` before `offered`, and the order is the argument.** `offered` varies with what is *selected* and `detected` does not, so a detection placed after it is promoted past the others the moment it is picked — "picking one detected model reordered the rest of them", which `index=choices.index(current)` cannot survive. Both front ends compose that one call with the same arguments (`webui.available_choices`, `cli._roster`), which is what keeps the REPL's printed row numbers and the picker's index meaning the same thing; `test_both_front_ends_offer_the_same_roster` pins the seam. Note the ordering test needs **three** detections — with two, both merge orders produce the same list and the assertion passes vacuously, which a first mutation run showed.

**Reading an endpoint and writing one are different functions, and conflating them was a measured regression.** `endpoints.normalize_endpoint` is for what a reader **types**: it adds a missing scheme, adds `/v1` to an empty path, and lower-cases the host. All three are required, not courtesies — measured against a live `mlx_lm.server` serving eight models, `127.0.0.1:8080/v1` (no scheme) returns `[]` because `Request` raises at construction, and `http://127.0.0.1:8080` (no `/v1`) returns `[]` because no OpenAI-compatible server answers at the root; both are what a reader actually types and both are indistinguishable from "server down". `endpoints.usable_endpoint` is for a value **read back** — it only accepts or rejects, never rewrites. The first version normalised on read too, and so rewrote the operator's own `SPEECHWRITER_BASE_URL`: an Azure deployment URL lost the `?api-version=` query it requires, and a LiteLLM or reverse-proxy front end serving the OpenAI API at the **root** gained a `/v1` that 404s. `build_agent` never probes, so each failed at the first turn with no log line. A configured endpoint is an operator's deliberate string; every character of it may be load-bearing.

Three details of the typed path. The scheme test is `"://" in raw`, **not** `urlsplit(raw).scheme`, because `urlsplit` reads the two spellings of one typo differently (`"localhost:8080"` → scheme `"localhost"`, `"127.0.0.1:8080"` → no scheme). The host is lower-cased but a netloc carrying userinfo is left alone, where case is significant — and lower-casing matters because roster dedup compares the *string* while `same_origin` compares the parsed origin, so `LocalHost` and `localhost` would otherwise be two rows that the credential boundary calls one server. And both functions are **total**, because `session_endpoint()` runs on the render path: a `ValueError` there is not a bad caption but a page that throws on *every* rerun with the offending text still in session state.

**The duplicate that normalising was reaching for is prevented on the read side instead.** A dotenv holding `http://127.0.0.1:8080/v1/` works fine — `list_models` rstrips it — and because `usable_endpoint` hands that value back untouched, detections against it carry the same string the configured pair does, and dedup on `(model, base_url)` collapses them to one row.

**The credential boundary is the configured origin, and it has to be drawn in *two* places.** `list_models` licenses forwarding the key with "no new disclosure: the chat client already sends the very same credential to this very same host" — exact, and it stops holding the moment the host is *typed*. `Settings.endpoint_api_key_for(target)` draws the line for the `/v1/models` probe; `ModelChoice.applied_to` draws the same line for the **chat client**, clearing `openai_api_key` unless the choice names the configured origin. Drawing it only at the probe was a hole rather than a guard, and a review caught it: the probe withheld the key while every *turn* went on sending it to the same typed host — measured on the wire as `Authorization: Bearer <the reader's real key>` — while the sidebar rendered "No credential sent". **The `self.base_url is None or` disjunct that used to sit in that test is gone, and must not come back.** It existed to carry the key through a *curated* (Anthropic) entry, which needs no endpoint credential because that client never reads one — without it, a detour through Claude and back stripped the key the configured endpoint still needed. With every entry now a configured or typed endpoint, the same disjunct is a carve-out with no owner: it would hand the reader's real `OPENAI_API_KEY` to any choice that arrived without a `base_url`. **A real key also goes only to an endpoint the operator *named*.** `Settings.endpoint_configured` records whether `SPEECHWRITER_BASE_URL` was actually set, and `endpoint_api_key` returns the placeholder when it was not. This became a live question the moment `base_url` gained a default: while unset meant "no endpoint", an `OPENAI_API_KEY` exported for some hosted service was simply never read; defaulting to `DEFAULT_LOCAL_ENDPOINT` would have started sending it to whatever process holds `127.0.0.1:8080`, on every turn, having configured nothing. Loopback bounds that; it does not make it intended. The default is a guess this repo makes on the reader's behalf, not a host they named — and *named* is what the whole boundary means. **`applied_to` must still be handed the *configured* settings**, which is why `cli._switch_model` applies to `configured` and not to `bundle.settings` — after one switch the latter's `base_url` is the previous pick's.

**Two things a review caught after this shipped, both about a boundary drawn in one place that needed two.** The credential guard covered the probe and not the chat client (fixed in `applied_to`, above). And `applied_to` gaining that behaviour gave it a **precondition** — it must be handed the *configured* settings — which `evals/run_experiment.py` then violated: it captured the judge as a `ModelChoice` and re-applied it to a `load_settings()` read *after* `apply_model` had blanked `SPEECHWRITER_BASE_URL`, so the judge's endpoint was compared against `None`, judged a stranger, and stripped of its key. Every judge call 401d, on the one path that has a judge to pin. It now captures the whole `Settings` (`configured_settings()`) and uses it as captured. **`evals/` is a third consumer of `config`'s model surface**; a change to `applied_to` or `resolve_choice` has to be checked there too.

Relatedly, `resolve_choice` answering `None` on ambiguity gave `apply_model`'s pass-through a case it was never written for — "no such entry" and "two entries by that name" are different, and passing the second through sets the id while leaving the endpoint alone, which is the mispairing `ModelChoice` exists to prevent. `config.matching_choices` is what lets a caller tell the two `None`s apart.

**Editing the endpoint is not a model switch.** No persist, no `get_bundle.clear()`, no thread rotation — pointing at a server changes what may be *offered*, never what is running. The three steps belong to the picker alone, and they sit one function away, so `test_editing_the_endpoint_is_not_a_model_switch` and `test_pointing_at_a_server_is_not_a_model_switch` exist because copying them here is the natural mistake. `apply_endpoint` does drop the previous server's detections, which is the cheap half of the binding rule.

**`cli.main` warns instead of exiting when no model can be called.** The gate used to `raise SystemExit(1)` while its own panel advised running a local server — advice reachable only by editing a dotenv and restarting. Commissions are still refused per turn (`test_a_commission_is_refused_while_no_model_can_be_called`); what is allowed through is the two commands that fix it. Do not restore the exit without also removing `/endpoint`.

**One model id served by two machines is a known ambiguity, and only half of it is fixed.** `apply_endpoint` drops the previous server's detections, but the *selected* pair is re-synthesised from the live settings by the `model_choices(settings)` tail — which it must be, or Streamlit resets the widget — so detecting the same id at a second endpoint puts two rows carrying the same label in the roster. The silent half is fixed: `resolve_choice` returns `None` on an ambiguous name rather than the first match, so `/model qwen` prints the table (whose `base_url` column tells them apart) instead of quietly picking a server. The browser keeps a cosmetic ambiguity — two visually identical options — and that is deliberate: the obvious fix, a host-suffixed label, is **measured to not work**, because the dropdown truncates at ~34 characters and `mlx-community/Qwen3.8-27B-4bit (local` is already 34. It would lengthen every label to fix nothing visible.

A shape that looks right and is **not**: a label that varies with roster context ("suffix the host only when two entries share an id"). `ModelChoice` is a `NamedTuple`, so the label is part of equality — an entry whose label depended on what else was offered would compare unequal to the one `model_choices` synthesises, appear twice, *and* leave the selected one unfindable, which is Streamlit's silent option-zero reset again. Whatever `local_choice` does, it must stay a pure function of `(model, base_url)`.

**`config.resolve_choice` is shared by `/model` and `--model`.** It was duplicated, and only the CLI's copy searched a roster containing the local entry — so the label a reader copies off the screen was passed through as a literal model id and 404'd at the first turn of every graded example. (`local_choice` labels an entry with the **bare id** now; the `(local)` suffix it used to carry earned its place only by contrast with hosted ids sitting beside it, and cost characters the picker truncates at ~34.) The eval harness resolves against `model_choices(load_settings())` for that reason. `--dry-run` now *rejects* `--model` and `--langsmith` rather than ignoring them, and priming happens once for every live path.

### Research is capability-gated, and it changes the agent's shape

One env var flips two coupled behaviors. Without `TAVILY_API_KEY`, `build_research_tool()` returns `None`, so:
- the `researcher` subagent is **absent from the subagent list entirely**, and
- `orchestrator_prompt()` swaps in a variant instructing the agent to flag unverified claims with `[VERIFY]`.

`TavilySearch` validates its key at *construction* time, which is why the tool is built conditionally and imported lazily. Both branches have tests.

### Memory: JSON snapshot, and persistence is the bundle's job

`StoreBackend` gives cross-thread persistence, but the only local `Store` is `InMemoryStore`, which dies with the process. `memory.py` snapshots it to `.speechwriter/memory-store.json` and rehydrates on startup. Swap `PostgresStore` in here to make it multi-user.

Durability is owned by `SpeechwriterAgent.persist()`, **not** the CLI — the CLI just calls it in a `finally`. Library consumers must call `bundle.persist()` themselves or learned voice profiles are lost.

Two correctness rules in `memory.py`, both with regression tests — preserve them:
- **Exhaust pagination.** `Store.search` and `list_namespaces` default to limits of 10 and 100 and silently truncate. `_paginate()` is the single place this invariant lives.
- **Never clobber.** An unreadable or wrong-shaped snapshot is renamed `*.corrupt` before starting empty, so a later save can't overwrite recoverable data.

### There are two front ends over one bundle

`cli.py` (Rich REPL) and the Streamlit app (`streamlit_app.py` → `app_pages/write.py` + `app_pages/browse.py`, glued by `webui.py`) are both thin views over the same `SpeechwriterAgent`. This is *why* durability (`persist()`), observability (`turn_config()`), and the resolved-ceiling label (`ceiling_label`) live on the bundle, not in either UI — a fact asserted above for the first two; the web UI is the second consumer that makes it load-bearing rather than hypothetical.
- **Build once.** `webui.get_bundle()` is `@st.cache_resource`; Streamlit reruns the whole script per interaction, so rebuilding would mint a fresh `InMemoryStore` each time and silently drop every voice profile learned this session. It stays **zero-arg** even though the model is now selectable — see the model-selection section for why parameterising it is a data-loss bug — and the deliberate exception to "build once" is `switch_model`, which persists, then invalidates with `get_bundle.clear()`.
- **`cli.py` has tests now** (`tests/test_cli.py`), and it did not before `/model` existed. The reason it earned them is the shape of its two failure modes: rebuilding before persisting, and a banner reporting the requested model rather than the built one, are both *silent*. The REPL is driven by monkeypatching `rich.console.Console.input` with a deliberately finite script — running past its end raises rather than blocking, so a dispatch bug fails CI instead of hanging it. `_dispatch` is pure (no console, no bundle, no environment) precisely so the command surface can be tested exhaustively for nothing.
- **Persist per turn, not on exit.** A closed browser tab runs no teardown, so `write.py` calls `bundle.persist()` after each turn (the CLI's `finally` has no analog).
- **A turn is recorded as data (`webui.Turn`), then replayed.** Live render and replay share `_render_event`, so they cannot drift. `_new_events` dedupes on message id because `stream_mode="values"` replays the whole message list every step.
- **The message→event decode is single-sourced in `transcript.py`** (`Event`, `iter_events`, `clip`) — a streamlit-free module both `cli.py` and `webui.py` consume, so the two front ends agree on *what* a message means; each keeps only its own formatting. `Event.text` is raw; the renderer clips/escapes. Keep `transcript.py` free of any Streamlit/Rich import.
- **A cancelled turn rotates the thread.** `submit_mode="stop"` raises a `BaseException` past `run_turn`'s `except Exception`, so a stopped turn never records or rotates. `run_turn` flags `_PENDING` while streaming; `_rotate_if_interrupted()` (first line of the next `run_turn`) rotates `thread_id` if the flag survived — the web analog of the CLI's post-interrupt rotation, so a half-executed graph is never resumed.
- **The browse page reads through `webui.documents(dir)`, which is `@st.cache_data`-cached** keyed on each file's name+mtime — so the expensive read+parse re-runs only when the folder changes, not on every rerun. `workspace.py` stays UI-free (no Streamlit import); the caching lives in `webui.py`.
- The page is `app_pages/browse.py`, deliberately **not** `workspace.py`, so it never collides with the `speechwriter.workspace` module or the `workspace/` data dir.

Two reader gotchas the web UI exposed:
- **`memory.all_items(store)` is the public exhaustive read** — the web UI lists profiles from the live Store through it, not the JSON snapshot. A hand-rolled `store.search(...)` stops at the default limit of 10 and shows a partial memory as whole.
- **`workspace.py` strips `---` front matter before rendering or counting.** The agent fences its header block with `---`; in CommonMark a `---` line right after a paragraph makes it a setext H2, so raw `st.markdown` renders the header as one run-on heading and its words inflate the spoken-length estimate. Bracketed cues (`[pause]`) are dropped from the word count too — they are delivered, not spoken.

## Measured spoken length is optional, and the optionality shapes the code

`workspace.measure_spoken_length()` synthesises a draft with Kokoro (MLX) and reports its real duration; `browse.py` shows it beside the `WORDS_PER_MINUTE` estimate. It lives behind `[project.optional-dependencies] audio` — `uv sync --extra audio` — because it pulls a torch/spaCy stack nothing else here wants, and CI installs no extras. Five things are load-bearing.

**The `mlx_audio` import is dynamic, and the model is loaded in two steps.** Not style — it is the only source state that type-checks in *both* environments. A static import is `unresolved-import` where the extra is absent (CI); a suppression for that is `unused-ignore-comment` where it is present, and `ty` **exits 1 on that warning** — so neither form is green everywhere, exactly the "state no source satisfies" the tool-pin rule describes. `import_module` sidesteps the import half. The load half is worse than it looks: `load_model` is annotated `model_path: Path` and *means* it — handed a Hub id as a `Path` it looks for a literal directory, misses the download branch and raises `FileNotFoundError` (verified) — so `load_model(model_id)` works at runtime but needs a suppression, and that suppression has no correct form either. `get_model_path(str) -> Path` is the half that resolves a repo id; the two calls chained are correctly typed and need no suppression at all. **Do not collapse them** — and if you go to verify the claim, do it **with the extra installed**: `ty` resolves `import_module` with a literal argument and types `load_model` precisely, so the error is real there, while in the CI state the module is unresolvable, everything is `Any`, and nothing fires. A review of this code checked the wrong environment and concluded the rule was fictional.

**`_spoken_text()` is the single corpus.** `Document.words` counts it and `measure_spoken_length` synthesises it, so the two figures the browser prints side by side describe the same words. Deriving either from a different string makes them disagree for a reason no reader can see.

**The measured figure is not a corrected estimate.** It times the words at a TTS voice's pace (140–180 wpm measured here) and adds no silence for a `[pause]` cue, laughter, or breath. 130 wpm may be the better guide to time on stage. Report the gap; don't "fix" `WORDS_PER_MINUTE` from it.

**Caching lives in `webui.py`, keyed on the draft's text** — `workspace.py` stays Streamlit-free, and the agent revises in place, so a path key would go stale where the text key does not. It is `max_entries`-bounded because each entry carries a WAV (~2.9 MB per spoken minute).

**The real-synthesis test is opt-in** (`SPEECHWRITER_TEST_AUDIO=1`), because it is the one test here that is neither free nor offline — the first run downloads the model. The default suite skips it and stays ~4s; the rest of the audio behaviour is tested with imports blocked, which needs no extra at all.

## Invariants to preserve

- **Building the agent must not call the model or the network.** This is what makes the entire test suite free and offline. Anything that would make `build_agent()` hit the wire belongs behind a lazy path.
- **The model's output ceiling is pinned in two tiers, never left to the client.** `build_agent` passes a *constructed* model (`agent.py:_build_model`), never a bare id string. Resolution order: **explicit `SPEECHWRITER_MAX_TOKENS` → `DEFAULT_MAX_TOKENS` (12288)**. The threat it guards is no longer LangChain's silent 4096 — that was the Anthropic path — but `ChatOpenAI`'s own `max_tokens=None`, meaning "let the server decide", which on a reasoning model is an unbounded thinking budget. Extended thinking bills against the same ceiling, so an unbounded one lets a subagent spend a whole response deliberating and emit no text, which deepagents forwards as an *empty* `status="success"` tool result (it walks back for the last message with text and finds none). The middle tier that kept a client-resolved ceiling is deleted, and read *There is one client* above before reinstating it: `init_chat_model` fills `max_tokens` from a profile only on the Anthropic path, so it could never fire here even for a profiled id. `settings.max_tokens` is only the override and is normally `None`; the resolved value lives on `SpeechwriterAgent.max_tokens`. `SPEECHWRITER_MAX_TOKENS` is validated `>= 1` at load time — a 0 or negative ceiling is accepted by `init_chat_model` and only fails at the first API call, far from the typo. **The ceiling is now sized against a window, not just a model**, so the second thing to preserve is that `DEFAULT_MAX_TOKENS` stays comfortably under `DEFAULT_LOCAL_CONTEXT_WINDOW` and that `ceiling_crowds_context` keeps reporting when an override does not. Two signals guard this at runtime, both tested: `TruncationWarner` (`observability.py`) counts responses that actually hit the ceiling, matching `stop_reason` *and* `finish_reason` across providers since `SPEECHWRITER_MODEL` is free-form; and the bundle owns that warner, handing it out via `SpeechwriterAgent.turn_config()`. (This bullet used to name a third signal, `test_default_model_still_resolves_through_tier_two`, one of only two assertions in the suite about a **dependency's** own behaviour. It went with tier 2. The langsmith cache canary under Gotchas is now the only one.) **Attach observability through `turn_config()`, not by hand-building `{"configurable": {...}}`** — same reasoning as `persist()`: the CLI is one of two entry points, and the README documents the other. Don't revert to `model=settings.model`.
- **`temperature`, `top_p` and `top_k` must never reach the request payload.** The rule survives the conversion; its *reason* inverted, so do not reason from the old one. It used to be that current Claude models reject them outright with a 400. A local server does the opposite — it accepts them, and silently — which is why the rule still holds and now matters more: `mlx_lm.server` and vLLM apply the sampling settings the model author shipped in its own `generation_config`, and any value we inject **overrides the model's own recommendation** with a guess. Qwen3.8 in particular ships distinct recommended settings for thinking and non-thinking modes. `build_agent()` never touches the wire, so nothing else here would notice a `langchain-openai` bump that began sending one by default; every *real* turn would silently sample differently instead. Don't add a sampling parameter to `_build_model` to "make output more consistent" — set it on the server, where it can be model-aware.
- **`import speechwriter` must stay lazy.** `__init__.py` exposes `build_agent` and `TruncationWarner` via module `__getattr__` so the heavy `deepagents`/`langchain` stack isn't imported eagerly. `test_import_speechwriter_is_lazy` spawns a subprocess to assert this — don't add a top-level import of `agent.py` to `__init__.py`.
- **`load_dotenv` targets `project_root / ".env"` explicitly**, never an upward walk (an ancestor `.env` could leak unrelated keys), and it is called inside `load_settings()` so `import speechwriter` has no side effects. Real shell env wins over `.env`.
- **The Store namespace is explicit** (`_memory_namespace` → `("speechwriter", "memories")`). deepagents' implicit-namespace mode is deprecated and removed in 0.7; the dependency is pinned `>=0.6.12,<0.8`.
- **The prompts may only name capabilities that actually exist.** `prompts.py` told the model to use its "planning tool (`write_todos`)" from the day it was written, and `create_deep_agent` has never bound one. Nothing structural could see it — `ty` checks Python and not prose, `ruff` checks syntax — so `test_prompts_only_advertise_tools_the_model_can_call` compares the rendered prompts against the tool surface: every backticked lowercase identifier must be a bound tool, a subagent reachable via `task`, **a tool owned by one of those subagents**, or an explicit entry in `_NON_TOOL_BACKTICKS`. That third source is load-bearing, not decorative: `researcher_prompt` advertises `tavily_search`, which belongs to the `researcher` and is never bound to the orchestrator's model — which is also why the test sets `TAVILY_API_KEY`, since without it the researcher is absent and its tool leaves the vocabulary with it. That allowlist is empty **on purpose** — a new backticked word should force a choice (bind the tool, or declare the word prose), not pass silently. Two details are load-bearing if you refactor it. The vocabulary is captured from what is bound to the **model**, not from the compiled graph's ToolNode (`agent.nodes["tools"].bound.tools_by_name`): the latter is a superset carrying `execute`, which middleware strips before the model sees it, so asserting against it would permit precisely the bug. And `bind_tools` fires when the graph *steps*, not when it is built, so the capture runs one turn against a recording stub — no network, so the offline invariant above still holds. The trailing `assert "task" in advertised` is an anti-vacuity canary: every other assertion is satisfied by an empty match set, so a pattern that stops matching would turn the test green while checking nothing. **When it fails, the fix is usually the prompt, not the test** — a new tool or subagent widens the vocabulary automatically, a new backticked prose word does not.

## Automation (`.claude/` and `.github/`)

The gates and invariants above are guarded by **two layers**, and the split is the point. There is no pre-commit and no git hooks.

1. **`.claude/` hooks — the inner loop.** Sub-second, fire on Claude Code's own events, and speak *to the model*: an exit-2 stderr lands in context so the diagnostic is fixed while the edit's intent is still live. They see the uncommitted tree, but only for edits Claude Code itself made.
2. **`.github/workflows/ci.yml` — the independent check.** Runs the same three gates on push to `main` and on every PR, in a clean clone with no `.env`, matrixed over Python 3.11/3.12/3.13 (~25s for the whole run). It covers what hooks structurally cannot: hand edits, contributors not using Claude Code, and fresh-environment-only breakage (the private third-party symbols noted under Gotchas). It also exercises the offline invariant — no API key is set anywhere in the workflow, so the day `build_agent()` starts needing the wire, CI goes red instead of quietly billing.

   **It reports; it does not block.** No branch protection rule requires these checks, so a red run is advisory — a merge or a push to `main` still lands. Making it a real gate is a repo-settings change, not a file: require the four checks (`ruff check` and `pytest + ty (py3.11|3.12|3.13)`) on `main`. Until then, don't describe CI as if it enforces anything. (The one exception is `release.yml` below, whose gate re-run does block a publish.)

Neither layer subsumes the other. The hooks are fast and land *in the model's context*, but only for edits Claude Code made and are bypassed by editing a file any other way. CI sees every commit in a clean environment, but out of band and with no channel back to the model — and, today, without the authority to stop anything. Three hooks, wired in `.claude/settings.json` — **all three blocking**; there is no advisory hook, by design (see below):

| Hook | Event | Behavior |
|---|---|---|
| `hooks/env-guard.sh` | `PreToolUse` on `Bash` | Blocks any Bash command referencing a `.env*` file or `secrets.toml`. **Exit 2** to deny. Measured 0.03s. |
| `hooks/ruff-ty-gate.sh` | `PostToolUse` on `Edit\|Write` | Runs `uvx ruff format` + `ruff check --fix` on the edited `.py`, then re-checks with `ruff check` and `ty check` — all at the **same pins as CI** (see below). **Exit 2** on remaining diagnostics. Measured 0.55s. |
| `hooks/pytest-gate.sh` | `Stop` | Runs `uv run pytest` if the working tree is dirty under `src/ tests/ skills/ .streamlit/ evals/ pyproject.toml uv.lock`. **Exit 2** on failure. Measured 0.02s clean / 3.0s dirty. |

Design rules to preserve if you touch these:

- **A hook must catch something no test can.** This is the rule that shrank the set. An advisory `invariant-hints.sh` used to restate the path invariant on a `config.py` edit and the skill-count assertion on a `skills/` edit — but the skill branch duplicated a gate that already *blocks* (`pytest-gate.sh` watches `skills` with `--untracked-files=all` precisely so a new `SKILL.md` trips `len(skill_dirs) == 4`), and the path branch duplicated the CLAUDE.md section above, which is already in the model's context at session start. Both were replaced by tests. **Before adding an advisory hook, check whether it is a test you have not written yet** — a hint is a suggestion that only fires for edits Claude Code made; a test blocks, runs in CI, and works for everyone.
- **The Stop gate must stay cheap in the common case.** It short-circuits on `git status --porcelain` in ~20ms and only then pays the ~3s suite (measured; `pytest` itself is ~2.5s and `uv` startup the rest). It fires whenever the tree is dirty under the watched paths, not when *this turn* touched them — a Stop hook has no reliable per-turn diff — so once `src/` has uncommitted work every turn pays it. At ~3s that is the intended trade. `--untracked-files=all` is load-bearing: `git diff` sees only *tracked* files, so a brand-new `skills/<slug>/SKILL.md` — exactly what trips the count assertion — would slip past untested.
- **Path matching lives in the scripts, not in settings.json.** The hook `if:` field is real, but its patterns are working-directory-relative and the leading-slash form is underspecified; `if: "Edit(/skills/**)"` can silently match nothing. Filtering inside the script is explicit and testable — each script parses the stdin payload for the key its own event actually carries (`ruff-ty-gate.sh` reads `tool_input.file_path`, `env-guard.sh` reads `tool_input.command`, and `pytest-gate.sh` reads only `stop_hook_active`, taking its paths from `git` rather than the payload), so each can be exercised directly — note the three invocations below are three different payload shapes for that reason:

  ```bash
  echo '{"tool_input":{"file_path":"'$PWD'/src/speechwriter/agent.py"}}' | .claude/hooks/ruff-ty-gate.sh; echo $?
  echo '{"stop_hook_active":false}' | .claude/hooks/pytest-gate.sh; echo $?
  echo '{"tool_input":{"command":"cat .env"}}' | .claude/hooks/env-guard.sh; echo $?   # want 2
  ```

- **`ruff-ty-gate.sh` pins ruff and ty to the same versions CI does, and a test keeps the three sites in step.** Floating locally while CI pins is not merely noisier or quieter — it admits source states that satisfy *neither*: a type-checker suppression comment is required by a version that cannot resolve a symbol and rejected as an unused-ignore by a version that can, so the gate goes green in the model's context and red on push. That is not hypothetical; it is what `a304a89` fixed. The pins live in four independent sites with nothing structural tying them — `ci.yml`, `release.yml`, the hook, and the commands in **Commands** above — so `test_tool_pins_agree_wherever_they_are_declared` asserts they agree, the same shape and the same remedy as `test_package_version_matches_pyproject`. **Bump all four together**; the test names every site and both versions when they drift, so it tells you where to look. It reads two spellings, which is why the doc can be a site at all: the named form (`TY_VERSION: "0.0.63"`, `TY_VERSION="0.0.63"`) and the invocation form (`uvx ty@0.0.63`). Two knock-ons worth knowing: pinning costs nothing at runtime (`uvx` caches per version — measured 0.55s, slightly *faster* than the floating gate it replaced), and the hook's failure banners now name the exact pinned command (`[uvx ty@0.0.63 check]`) so what it reports is what you can re-run.
- **Missing tooling is non-blocking but *visible* — exit 1, not 0.** A missing `uv`/`jq`/`python3` must never masquerade as a lint or test failure, so it never exits 2. But it must not exit 0 either: stderr on exit 0 is swallowed, so a gate that has quietly stopped running looks exactly like a gate that is passing. Exit 1 is non-blocking *and* surfaces the note. Both quality gates follow this.
- **`env-guard.sh` inverts that rule, deliberately.** It is the one hook guarding credentials rather than code quality, so it **fails closed**: no `python3`, or an unparseable payload, and it denies the command. A credential guard that silently switches itself off when a parser is missing is worse than no guard, because you believe you have one. Its scope mirrors the tool-level `Read(./.env.*)` deny rule exactly — `.env.example` included, though it is committed and secret-free — so the two cannot disagree; narrowing it is one line.
- **`permissions.deny` is tool-scoped, and Bash routes around it.** `Read(./.env)` stops the `Read` tool and nothing else; `cat .env` was never covered by any rule, and auto mode makes reading files via `cat`/`sed`/`grep` the *default* path. That gap is what `env-guard.sh` exists to close — remember it whenever you add a `deny` entry expecting it to be airtight.
- `pytest-gate.sh` honors `stop_hook_active` so it can never re-block a turn it already blocked.
- **Add an import and its first use in the same edit.** `ruff-ty-gate.sh` runs `ruff check --fix`, which deletes a just-added import as unused (F401) before you have written the code that needs it — silently reverting your edit. Writing the usage first works too, at the cost of one blocking failure.
- **Mutation-test a new test before trusting it.** Break the code it covers, confirm it fails, restore. Nothing else here would catch a test that passes vacuously.
- **Restore a mutation from a working-tree copy — never `git checkout -- <file>`.** This destroyed several hours of uncommitted work once and is worth the line. Mutation testing happens *while* a change is in progress, so the file you are breaking is almost always dirty; `git checkout --` restores **HEAD**, silently discarding the very change the new test exists to cover. Worse, it fails quietly: the tree looks clean, the suite goes green, and it is now measuring the *old* code. `cp` the file aside first and `cp` it back, or reverse the exact string replacement. The same rule kills `git stash`, `git restore` and `git checkout .` for this purpose. It applies with double force to a subagent, which cannot see what the rest of the tree is mid-edit.

Writing a `.env` value is therefore a **user action, not a Claude action**: ask the user to make the edit, then verify indirectly (assert a variable is non-empty, run the offline suite) without printing anything. The guard fires on the literal token in *any* Bash command, prose included — a heredoc writing documentation about it is blocked too. Use Write/Edit for that, as the hook's own message says.

**And that scope collides with a test.** `test_env_example_documents_every_setting` is a fifth consumer of `config.py`: it extracts every `SPEECHWRITER_[A-Z_]+` token from the source and asserts each appears in the example template. But that template matches the deny rules and `env-guard.sh`'s pattern alike — deliberately, so the guard and the rules cannot disagree. So **adding a `SPEECHWRITER_*` knob to `config.py` turns the Stop gate red in a way Claude structurally cannot clear**: it must ask the user to add the documenting line. Expect that, rather than rediscovering it as a mystery failure.

### Releases are automatic, and the version lives in two files

`.github/workflows/release.yml` tags and publishes a GitHub Release, unattended, when
`[project] version` in `pyproject.toml` changes on `main`. There is no draft step — it goes live.

That is only safe because of three guards, each load-bearing:

- **The trigger is `paths: ["pyproject.toml"]`, which also fires on every `uv add`.** So a
  `check` job reads the version and stops unless `v$VERSION` is a tag that does not exist yet; a
  dependency bump lands as `check ✓ / release ⊘ skipped`, not a spurious release. That job
  deliberately runs no `uv sync` and never sets up uv — the no-op is the common path and should
  cost seconds. It reads the version with `tomllib` on the runner's own `python3` (ubuntu-24.04
  ships 3.12), and every failure mode there is loud: a missing key or a bad parse fails the step
  rather than tagging something wrong.
- **The `release` job re-runs all three gates before tagging.** `ci.yml` runs the full matrix on
  the same commit, but nothing orders the two workflows, so this re-checks on the 3.11 floor
  rather than tagging a commit whose verdict has not landed. **This is the only place in the repo
  where a failing gate actually stops something** — the counterpoint to "it reports; it does not
  block" above.
- **The version is two independent literals** — `[project] version` in `pyproject.toml` and
  `__version__` in `src/speechwriter/__init__.py`. Nothing structural ties them: hatchling builds
  from the first, `import speechwriter` reports the second.
  `test_package_version_matches_pyproject` is what makes an unattended release safe, precisely
  because it runs inside that gate re-run — a half-done bump fails the job instead of publishing a
  release whose installed package still reports the old version. **Bump both, in one commit.**

Two mechanics worth not re-deriving. `gh release create` creates the tag itself at
`--target $GITHUB_SHA`, so there is no `git tag`/`git push` step and no bot git identity to
configure. And `permissions` is asymmetric on purpose: `release.yml` needs `contents: write` for
that call, `ci.yml` stays `contents: read`.

## Skills

Each `skills/<slug>/SKILL.md` is loaded on demand by the agent (progressive disclosure — the description tells the agent when to read the body). `test_all_skills_have_valid_frontmatter` enforces the contract:

- YAML frontmatter with `name` **matching the directory slug** and a non-empty `description`.
- Body sections: `## Overview`, `## When to Use`, `## Instructions`, `## Pitfalls`.
- The test hard-codes `len(skill_dirs) == 4` — **adding or removing a skill requires updating that assertion.**
- `test_orchestrator_prompt_names_every_skill` additionally requires each slug to appear in the parenthetical list in step 4 of `orchestrator_prompt()`. Progressive disclosure cuts both ways: the agent only reads a `SKILL.md` if it knows the skill exists, so a skill absent from that list is dead weight on disk. Slugs are matched in their prose form (`delivery-and-cadence` → "delivery & cadence"); if a new skill does not fit that shape, name it in the prompt however reads best and widen the normalisation in the test.

## Gotchas

- **`tests/test_build.py` reaches into three private third-party symbols**, any of which can vanish on a dependency bump: `deepagents.middleware.filesystem._check_fs_permission` (the sandbox test, the likely casualty), `agent.nodes["tools"].bound.tools_by_name` (the prompt-vs-tool test), and `ChatOpenAI._get_request_payload` (the payload test — it was `ChatAnthropic`'s until the hosted client was removed, and the two sibling assertions collapsed into one). That is deliberate — a rename breaks them loudly, which is the failure mode we want. `.claude/hooks/pytest-gate.sh` names the same three in its dependency-change hint, so they are two sites and must be changed together. It also imports `yaml`, which is **no longer** transitive-only: `pyyaml>=6.0` is declared in `[dependency-groups] dev` as of `d4265dd`.
- **`[tool.ruff.format] exclude = ["*.md"]` is load-bearing — don't drop it.** Ruff 0.16 formats Python code blocks inside `.md`, which would make the formatter the only part of the toolchain that reaches into docs: `ruff check` skips Markdown entirely (`No Python files found`), and `hooks/ruff-ty-gate.sh` filters to `*.py`/`*.pyi`. Without the exclude, the documented `uvx ruff@0.16.0 format .` silently rewrites the hand-typeset fences in `README.md` — and in this file, whose **Commands** block is column-aligned by hand — so an unrelated commit picks up a docs diff. With it, the formatter sees 20 Python files and `.` is safe for the hook, CI, and the command line alike.
- `workspace/` and `.speechwriter/` are gitignored runtime output — `load_settings()` creates them on startup, so a missing folder never fails the first draft.
- The CLI rotates `thread_id` after a `KeyboardInterrupt` so it never resumes a half-executed graph; that intentionally drops prior conversation context.
- The orchestrator is given **no direct tools** (`tools=[]`). Research is delegated so noisy search results never crowd the writing context. Add new capabilities as subagents unless the orchestrator genuinely needs them inline.
- **There is no planning tool, and that is not an oversight.** `create_deep_agent` binds exactly `ls`, `read_file`, `write_file`, `edit_file`, `delete`, `glob`, `grep`, `task` — no `write_todos`. deepagents 0.6 had no `TodoListMiddleware` at all; 0.7 installs it only for the OpenAI-Codex harness profile. The staged rhythm lives in `prompts.py` instead. If you ever want the tool, it is `create_deep_agent(middleware=[TodoListMiddleware(system_prompt="")])` from `langchain.agents.middleware` (the empty `system_prompt` trims LangChain's default prose, which otherwise duplicates the tool's own schema description) — but do not re-add a *claim* that planning is automatic without binding it, or the system prompt goes back to advertising a tool the model cannot call — `test_prompts_only_advertise_tools_the_model_can_call` fails if you do.
- **`langsmith.utils.get_env_var` is `lru_cache`d, so `load_settings()` clears that cache right after `load_dotenv`.** The first read of `LANGSMITH_TRACING` is the one that sticks for the process, so anything touching tracing state at import — a module-level `Client()`, a `tracing_is_enabled()` — would otherwise cache "off" *permanently* for a value that exists only in `.env`, with nothing raised. Tracing just never happens while every setting still reads as correct, which is indistinguishable from a project whose traces aged out of retention. This used to be an unwritten ordering rule that only `build_agent()` happened to satisfy; clearing the cache makes the order irrelevant for **all three entry points** (CLI, Streamlit, library consumers), which is why the fix lives in `config.py` and not in `agent.py`. `test_load_settings_reopens_the_langsmith_env_cache` guards it, and its first half is an anti-vacuity canary: it asserts *directly* on `get_env_var` rather than through `tracing_is_enabled()`, which returns early on three context-var paths before it ever consults the cache — a future default there would let the test pass while exercising nothing. That canary is the suite's **second** assertion about a dependency's own behaviour rather than our code (see the ceiling bullet's `test_default_model_still_resolves_through_tier_two`); if it fails, langsmith stopped caching and the `cache_clear()` is obsolete — re-read this bullet, don't "fix" the test. Note `cache_clear` is invisible to `ty` (`@overload` stubs shadow the `lru_cache` wrapper): `config.py` reaches it through `getattr` and degrades quietly, the test binds it directly and fails loudly, and that asymmetry is deliberate.
- **Store keys are not one shape.** A write through the backend keeps its leading slash — `/memories/mayor.md` lands as key `/mayor.md` — while tests and any code seeding the Store directly use the bare `mayor.md`. Both coexist in practice, and `browse.py`'s `_humanize` title-cases the raw key, so a genuine agent-written profile renders as **"/Mayor"** in the Memory expander. Strip the slash at the presentation layer if you care; don't "fix" it in the backend.
- **`evals/` is gated, and its counts are hard-coded on purpose.** `evals/datasets/*.json` holds 55 LangSmith evaluation examples and `evals/validate_datasets.py` checks them against the live contract — it recomputes every word count from `WORDS_PER_MINUTE`, resolves save paths through `load_settings()`, and rejects any tool, subagent or skill slug that is not real. `test_eval_datasets_match_the_live_contract` runs it in a **subprocess**, pinning `SPEECHWRITER_HOME` to the real repo — the one place in the suite where a `tmp_path` would be wrong, since the committed datasets are what is under test. The subprocess is the point: in-process, `load_settings()` would read the project's secrets file into `os.environ` and leak a real Tavily key into every test that ran afterwards. `EXPECTED_COUNTS` names a count per file, so **adding or removing an example requires updating it** — the same deliberate friction as `len(skill_dirs) == 4`.
- **The datasets are mirrored to LangSmith, and the mirror is push-only.** `evals/sync_datasets.py` checks that the four remote `Speechwriter: <stem>` datasets match `evals/datasets/*.json` exactly; `--push` makes them match, so an edit made in the LangSmith UI is overwritten rather than merged back. Local is the source of truth. Three things it encodes are worth not re-deriving. **Never diff against `langsmith dataset export`** — that CLI path drops `metadata` entirely, so a comparison built on it reports all 55 examples as having lost the field that carries their grading semantics (`path_semantics`, `grade_tool_calls_after_message_index`, `max_clarifying_questions`); the server holds it fine, and `Client.list_examples` returns it. **LangSmith injects `dataset_split` into every example's metadata**, so a naive equality check flags all 55 as drifted on a key no local file ever wrote — `SERVER_INJECTED` strips it on the remote side and `load_local` *refuses* it on the local side, because declaring it claims a field the server overwrites. And `DESCRIPTIONS` lives in the repo rather than only on the server: the trajectory one is the only place that tells a grader `expected_trajectory` is a **reference** path and that exact sequence matching fails legitimately-correct runs — and `Client` has no `update_dataset`, so a description can be *set* at creation and only *reported* thereafter. Exit codes are `0` in sync / `1` drift / `2` could-not-check, and the third is never `0` for the reason the hooks exit 1 rather than 0 on missing tooling: a check that has quietly stopped running looks exactly like one that is passing. It needs a key and the network, so it is **not** a pytest gate — the pure diff is tested offline instead, and `DESCRIPTIONS` is tied to `EXPECTED_COUNTS` by `test_sync_roster_matches_the_validator` (they are two independent literals: the validator runs its whole check at import and exits, so nothing can import the roster from it). **A fifth dataset must be added to both**, or it is validated but never mirrored.
- **The scorers are pure, and what they cannot read scores `None` — never `1.0`.** `evals/evaluators.py` takes a `RunRecord` (the final text plus every tool call, in order) and returns `Score` rows; no model and no network, so it is tested offline like everything else. `evals/run_experiment.py` is the harness: `--dry-run` scores a canned run for free, the live path invokes the agent once per example, and `--langsmith` records it as an experiment against the mirrored dataset. Four things are load-bearing. **`expected_trajectory` is never scored** — the dataset's own LangSmith description says exact sequence matching fails legitimately-correct runs, so it is reported as a similarity string while the pass/fail axes are `required_tools`, `required_subagents`, the write-path fields and `order_constraints` (prefix-matched and pairwise, exactly as each example's `path_semantics` and `order_constraint_semantics` declare). **The `must_not_contain` quoting convention is the mechanical transform it was locked to be**: `split_must_not_contain` sends quoted entries to a literal substring check and bare ones to the judge, which is *why* `validate_datasets.py` rejects a half-quoted entry. **Word counts come from `workspace.spoken_words`**, extracted out of `Document.words` so the eval and the browser cannot disagree about the same draft — header block and `[pause]` cues dropped in both. And **9 of the 12 committed `order_constraints` parse; the other 3 have a prose side and land in the unscored tail**, counted by `coverage()` and printed separately rather than folded into a pass rate. Its test asserts that from **both** sides — a lower bound on how many parse, and an upper bound naming the three that must stay unscored — because the lower bound alone is satisfied by a checker that scores everything `1.0`, which is how it passed the first mutation run.
- **Each graded run gets its own `SPEECHWRITER_HOME`, and writes are read back off disk.** Half the criteria are about *where* the agent wrote, so a shared workspace would let one example pass on a file the previous one left behind. And a subagent's tool calls never surface in the orchestrator's message stream, so a `researcher` that correctly saved to `/workspace/research/` would look like it wrote nothing — the disk is ground truth for path criteria, the message stream is ground truth for ordering, and both feed one `RunRecord`.
- **A banned phrase is a question, not a verdict.** `must_not_contain`'s quoted entries are literal substrings, and a substring search cannot tell **use** from **mention** — a speech that says *"they'll tell you to follow your passion"* in order to reject it is doing exactly what the brief asked ("Don't tell them to follow your passion"). A clean draft still resolves deterministically with no model call; a **hit escalates** to a narrow use-or-mention judge that sees the phrase plus its neighbouring sentences, because quoting-to-reject routinely straddles a sentence break. Only *mention* passes, and the escalation is reported per phrase so an allowed hit is visible rather than silently forgiven. Under `--no-judge` a hit stays **unscored**, never a guess. This is safe because the two entries where presence is a violation regardless of framing — `"Pinehurst"` and `"Saved to src/speech.md"` — have no plausible mention reading *and* carry judge-side twins (`"any allusion to a project that ran over"`, `"any claim that the speech was saved to src/speech.md"`, plus `forbidden_write_attempt_paths` on the trajectory side). The validator's deferred "two fields" fix is still open; escalation buys the same correctness without re-authoring 45 entries, and the escalation log is what would tell you which entries actually need the split.
- **`rag` is judged on the saved artifact, not just the reply — and `--keep` is how you find that out.** The researcher prompt says "Keep the return short; the detail lives in the file you saved," so grading `run.text` alone marks a correctly-sourced run down for obeying its own instructions. It did: `required_source_properties` failed on "resolvable URL" until `extract()` captured file *contents* as well as paths and `graded_text()` routed them to the judge — the saved note held **112 URLs across 33 domains**, and the example went 14/16 to 16/16. `--keep` leaves each run's home on disk; reach for it first whenever an eval result surprises you, because in this suite every measurement bug so far has made the agent look **worse** than it is (lost signal reads as absence, absence reads as failure).
- **A cheap check that errs in only one direction can still be trusted — on that one side.** Two scorers approximate: `count_questions` is a bare question-mark tally, and the `must_not_contain` literal scan is a substring search. Both **over**-report and never under-report — rhetorical questions inside a draft inflate the tally, and a substring is found whether the phrase is *used* or *mentioned* — so at-or-under the cap and a clean scan are both **sound passes needing no model**, while only the unsound side escalates to a judge. That asymmetry is the whole design: making them judge-only would discard certainty actually in hand and pay for a model call on every clean run. The question isn't whether a cheap check is accurate, it is *which way it errs*. Both were rescuing real runs, not hypotheticals — a compliant ask-and-stop reply scored 5 question marks against a cap of 3 because its three numbered questions carried sub-questions, and would have failed outright.
- **The intake branch is non-deterministic, and the eval is measuring that.** On the maximally bare brief ("Write me a speech about resilience. Make it good.") two runs of the same example diverged completely: one asked three questions and stopped, writing nothing; the other drafted 735 words. Step 1 of `orchestrator_prompt` says "two or three sharp questions, **then proceed** on sensible assumptions" and never says to wait, so both readings are licensed and the model picks one per run. `intake-bare-resilience-request` requires the stop (`must_cover[2]`, "the turn ends at the questions"), which is coherent — the suite models turn boundaries properly, with seven multi-message fixtures and a `is_turn_1_for`/`requires_prior_turn` pair. **Do not read a single failing run here as a prompt bug**; n=1 on this example says nothing. Tightening step 1 to say *when* to stop would remove the ambiguity, but that is a product decision about intake behaviour, not a defect fix.
- **The ambiguity is deliberate, and a tightening was tried and reverted.** All three datasets license *both* branches on the bare brief: `single_step` carries `metadata.soft_pass_branch: "proceed_with_stated_assumptions"` plus a numbered **SOFT PASS** paragraph in its `grading_notes`, `trajectory` says "TWO trajectories are correct and the grader MUST accept either", and `final_response` says "both are fully correct and neither may be marked down". The failure all three name is the same and it is **not** drafting — it is *drafting on silent, unstated assumptions*, which the prompt already forbids. A 44-word tightening that spelled out what to do "if you draft" was measured over three runs and **made it worse**: 3/3 drafted where 1/2 had previously stopped, because the added words gave operational detail for one branch only and made it the salient one. Reverted. **Do not force a stop here** — it would contradict committed ground truth in three files.
- **`--model` moves the system under test, never the instrument.** `run_experiment.py --model` takes a roster label or an id and applies it through `os.environ` *before* `prime_environment()`, which works because `load_dotenv` never overrides an already-set variable. Two halves are load-bearing. A resolved choice sets **both** `SPEECHWRITER_MODEL` and `SPEECHWRITER_BASE_URL`, never one — `base_url` selects the server, so setting the id against whatever endpoint happened to be exported sends it somewhere it is not served. And the judge is **pinned to the pair in force beforehand** (`configured_settings()` captured before `apply_model`, threaded through `run_langsmith` → `grade`), because `grade()` builds its model from `load_settings()` and reads the same `SPEECHWRITER_MODEL`: left alone, comparing two models would grade each one with itself, changing the instrument and the subject together. `--dry-run` skips both, since it never reaches a judge. `experiment_prefix` carries the model *and its host* (`speechwriter-{dataset}-{model}-{netloc}`) — the `-local` suffix it used to carry separated locally served from hosted, which now separates nothing, while the distinction that survives is between two **servers**. Two models' (or two machines') experiments must not be indistinguishable in the mirror, which is the reason the model is selectable at all.
- **The eval judge asks for structured output by `function_calling`, not the library default.** `evals/evaluators.py` defines `JUDGE_STRUCTURED_OUTPUT_METHOD` and a `_structured` helper that all three `with_structured_output` call sites go through. `langchain-openai` 1.6 defaults to `method="json_schema"`, which sends `response_format: {"type": "json_schema", …}` — a *server* feature `mlx_lm.server` does not implement (verified against the installed pin). While the judge was hosted this never showed; served locally it would 400 every judged example uniformly enough to read as "the judge disagrees" rather than "the judge never ran". One helper rather than three call sites passing the same keyword, because a call site that forgot it would fail at the endpoint in whichever criterion happened to use it, not here.
- **The judge gets the example's `grading_notes`, because they are how the criteria apply.** `must_cover`/`must_not_do` on the intake examples describe the ask branch only; the soft pass for proceeding, and the rule that one compound question may bundle three gaps, live in `grading_notes`. Withholding them makes the judge strictly harsher than the dataset — a live run that did the documented soft pass verbatim ("states assumptions and invites correction") scored 3/9. This was the **fifth** measurement bug of the same family, and like the other four it made the agent look worse than it is.
- The agent revises `workspace/speeches/<slug>.md` **in place**; copy it aside first if you want to diff a re-run against the previous draft.
